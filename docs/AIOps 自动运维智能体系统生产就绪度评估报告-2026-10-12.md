## 二、生产级缺口（按风险优先级排序）

### P0 — 数据生命周期失控（最紧迫）

**证据**：`data/` 目录 **133GB**，其中 `sandbox/` 84G + `qoder/` 48G。

- **风险**：沙箱/修复产物无 TTL 清理策略，磁盘将持续线性增长直至写满。一旦磁盘满，MySQL/Redis/Loki 连锁故障，且 `data/` 在 git 白名单内（评测资产），误提交风险并存。
- **建议**：
  1. 立即加 `scripts/cleanup-sandbox.sh`：按 mtime 清理 `data/sandbox/` 与 `data/qoder/` 中 N 天前产物（建议 7 天），watchdog 每日调用或 crontab；
  2. 沙箱产物应存独立卷/tmpfs，与 `data/` 的持久数据（审计/令牌/清单）物理隔离；
  3. 在 `demo_cli.py doctor` 增加磁盘水位检查项（>80% 告警）。

### P0 — 日志无轮转

**证据**：全部组件 `nohup > *.log` 追加，无 `RotatingFileHandler` / logrotate；`app_prober.log` 已 3.1M、`log_surge_detector.log` 2.0M 且持续增长。

- **风险**：长期运行后单文件 GB 级，排查时 grep 缓慢；磁盘同 P0 风险叠加。
- **建议**：统一改 `TimedRotatingFileHandler`（按天轮转，保留 14 天），或外部 logrotate.d 配置。改动集中在 6 个入口的 logging 初始化，半天工作量。

### P1 — 无备份与恢复演练

**证据**：无 mysqldump / 快照脚本；`data/`（审计、令牌注册表、用户表、监控清单）单点。

- **风险**：本机故障 = 审计链与配置全丢；令牌注册表丢失会导致全部静态令牌失效（自动化调用中断）。
- **建议**：
  1. 每日 `mysqldump`（生产档 MySQL 3316）+ `data/` 关键 JSON（`console_tokens.json` / `monitored_apps.json` / `console_users.json`）打包异地；
  2. 每季度做一次恢复演练（备份不演练 = 没有备份）。

### P1 — 无开机自启 / 崩溃恢复链不完整

**证据**：无 LaunchAgents / crontab；watchdog 本身无守护（watchdog 死了无人拉起——经典「谁来守护守护者」）。

- **现状缓解**：容器 `restart: unless-stopped` 覆盖了依赖层；但 7 个 Python 组件在宿主机重启后全部静默停止。
- **建议**：macOS 用 `launchd` plist（`KeepAlive` + `RunAtLoad`）托管 watchdog，由 watchdog 拉起其余组件——形成「launchd → watchdog → 6 组件」三级恢复链。

### P2 — 演示/生产档位混用风险

**证据**：当前 `.env` 为 `AIOPS_MODE=production`，但 `demo-up.sh` 强制 demo 档、`start.sh` 无档位提示。watchdog 拉起组件时继承启动环境，若 watchdog 由 demo-up.sh 启动而后台组件期望生产档，会出现**同机两档并存**的隐蔽状态。

- **建议**：
  1. `start.sh` / `demo-up.sh` 启动前打印醒目档位横幅（`AIOPS_MODE=production` 时红色警告）；
  2. watchdog 拉起前校验目标组件的档位与自身一致（读 `.env` 比对），不一致拒绝拉起并告警；
  3. 长期看，演示与生产应分目录/分端口段，杜绝同机混跑。

### P2 — 单点与资源边界

- **Temporal dev server**：单容器无持久化保证（dev server 重启清空工作流历史），生产应换正式 Temporal 集群或至少持久化存储；
- **Ollama 单点**：LLM 链路无降级（模型不可用时 triage 应明确转人工而非阻塞）——需确认当前行为；
- **资源限额**：Python 组件无内存/CPU 限额（cgroup/ulimit），沙箱构建（docker build）可能耗尽资源影响 BFF 响应。

## 三、专业建议（落地路线）

### 立即可做（本周，低成本高收益）

```bash
# 1. 磁盘止血（30 分钟）
scripts/cleanup-sandbox.sh   # 新增：find data/sandbox data/qoder -mtime +7 -delete
# 2. 日志轮转（半天）
# 6 个入口统一 TimedRotatingFileHandler(when='midnight', backupCount=14)
# 3. 档位横幅（10 分钟）
# start.sh 顶部 echo 当前 AIOPS_MODE，production 时红色警告
```

### 短期（两周内）

- launchd 自启 plist（watchdog 托管）
- 每日备份脚本 + 首次恢复演练
- doctor 增加磁盘水位 + 档位一致性检查项

### 中期（一个月内）

- Temporal 持久化（或明确接受 dev server 语义并文档化）
- 组件资源限额（ulimit / 容器化迁移）
- LLM 不可用时的降级路径确认与补测试

## 四、一句话结论

> **这是一套「演示级完成度极高、生产级运维欠账明确」的系统。** 核心链路的工程质量（闸门/幂等/审计/安全）已达企业级，但**数据生命周期、日志轮转、备份恢复、自启链条**这四个生产运维基本功是当前最大缺口——它们不改变系统能力，但决定系统能否「无人值守跑一年」。建议按 P0 → P1 → P2 顺序补齐，预计总投入 3-5 人日。
