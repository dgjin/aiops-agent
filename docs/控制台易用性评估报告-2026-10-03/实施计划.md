## 1. 范围

**纳入**：报告中的全部 15 项发现（A1–A5、B1–B5、C1–C5）+ 取证时额外发现的 2 项（审计 `result` 语义错误、`protected` 演练分支兜底补丁恒失败）。

**不纳入**：需求类新增（如多租户、RBAC 细粒度权限、告警规则可视化编辑）；架构级改造（Temporal 接入方式、沙箱运行时更换）。

**原则**：
- 每工作包**独立提交、独立可验收**，不做大爆炸式重构。
- 审计/接口**只增字段、不删不改语义**，保证历史数据与前端兼容。
- 涉及前端的一律 `tsc --noEmit && vite build` 重建 `web/dist`（BFF 静态托管，无需重启 BFF）。
- 验收一律沿用报告的证据方式：**单测 + 接口原始返回 + 截图**。

## 7. 开工前必须先确认的前置条件

1. **鉴权方案（阻塞 WP3，进而阻塞 WP6）**：静态 Token（`AIOPS_CONSOLE_TOKEN`）/ 反向代理 Basic Auth / 企业 OIDC 单点登录，选哪种？是否要求"读接口也保护"？
2. **操作身份粒度**：只要"能区分是谁"，还是需要按角色区分（如二级审批需更高级别）？
3. **是否允许改 `web/dist` 构建产物**（需 `npm run build`，本机已具备 Node）。
4. **执行窗口**：实施中的验证会临时发起演练流程（不发布），确认可接受。
5. **优先级确认**：是否接受"先做最小闭环（WP1+WP2+WP5）"再排其余。
